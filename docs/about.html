作った人と、作り方

ジャズピアノを習っている社会人と、AI秘書のClaude Code。設計と検収は人、コードは秘書。

Who

作った人

ジャズピアノを習っている社会人です。目標は即興演奏（アドリブ）。レッスンで「音程を聴き分ける耳が土台」と教わって音程当てのアプリを探しましたが、「なぜそれがアドリブにつながるのか」まで教えてくれるものが見つかりませんでした。それなら自分の言葉で作ろう、と。

プログラミングは専門ではありません。AI秘書（Claude Code）に「こう作って」と頼み、できたものを自分の耳と目で検収する、を繰り返して作りました。

How

アプリの作り方

  1. まず理屈を一文にした。「アドリブ＝頭に鳴った音を、その場で鍵盤に出すこと。途中で『このコードの何度か』という翻訳が入る。音程トレーニングは、その翻訳を速くする練習」。この一文が設計図です。
  2. レベルの順番を、ジャズで意味のある順に決めた。難しさ順ではなく、骨組み→明暗→ガイドトーン→緊張→色→実戦→コード上の度数→フレーズ聴き取り。
  3. 音にこだわった。最初のピアノ音は正弦波の足し算で、「音がしょぼい」の一言で却下。倍音のずれ・弦2本のゆらぎ・打鍵音・残響まで計算で作り直しました。音源ファイルはありません。
  4. 1枚のHTMLにした。ダブルクリックで動き、データはブラウザの中。配るのも動かすのも軽い。
Making of this site

このサイトの作り方

このサイト自体も、「Webページを作って世界に公開するまで」を体験するために、同じ二人三脚で作りました。3段階です。

  1. 1枚のLPを作って、無料で仮公開構成案を3つ出して1つ選ぶ → PCとスマホで検収 → Netlify Drop にフォルダを渡すだけでURLが出た（1時間で消える練習用）
  2. GitHub Pages で本公開1枚のHTMLを「中身（HTML）・見た目（CSS）・動き（JS）」に分割。git で管理し、GitHub に送る（push）と自動で公開される。「直す → 送る → 反映」が更新の基本形
  3. 複数ページに育てるページが増えると共通のヘッダー・フッターの管理が面倒になる → 「共通の枠」と「各ページの中身」を分け、小さなPythonスクリプト（build.py）で組み立てる。これが静的サイトジェネレーターの正体

お問い合わせフォームの受け口は、サーバーの代わりに Google Apps Script（Googleの無料の小さなプログラム置き場）で作りました。送られた内容はスプレッドシートに溜まり、制作者にメールで知らせが届きます。静的サイト（ただのファイルの束）でも、こうすれば「受け付ける」ことができます。

使った道具：HTML／CSS／JavaScript（Web Audio API）、Python、git、GitHub Pages、Google Apps Script、Google Fonts（Fraunces・Manrope）。有料のものはありません。

元データと組み立てスクリプトは GitHub で見られます。
