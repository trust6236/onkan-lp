# 音感トレーニング — 紹介サイト

自作アプリ「音感トレーニング（アドリブへの耳をつくる）」の紹介サイトです。
「Webページを作って公開するまで」を体験・理解するための練習も兼ねています。

公開URL: https://trust6236.github.io/onkan-lp/

## フォルダの構造（第3版：複数ページ＋自作の組み立てスクリプト）

```
web_lp/
├─ build.py            … 組み立て役。実行すると docs/ が出来上がる（自作の静的サイトジェネレーター）
├─ templates/
│   └─ base.html       … 全ページ共通の「枠」（ヘッダー・メニュー・フッター・<head>）
├─ content/            … 各ページの「中身」だけ（先頭に title: / description: の行）
│   ├─ index.html      … トップ（LP）
│   ├─ howto.html      … 使い方
│   ├─ about.html      … 作った人と、作り方
│   ├─ news.html       … お知らせ
│   └─ contact.html    … お問い合わせ（フォーム）
├─ static/             … そのまま公開されるもの
│   ├─ css/style.css   … 見た目（全ページ共通）
│   ├─ js/main.js      … 動き（デモの音、お問い合わせの送信）
│   ├─ images/         … 画像（アプリの画面、OGP画像）
│   └─ favicon.svg     … タブのアイコン
├─ docs/               … ★公開されるフォルダ（build.py が作る。手で直さない）
└─ README.md           … この説明書き
```

考え方はこうです。

- **中身（HTML）・見た目（CSS）・動き（JS）** を分けるのが Web の基本形（第2版で分けた）
- ページが増えると、共通のヘッダー・フッターを全ページにコピペするのが面倒で、直し漏れも起きる
- だから **「共通の枠」と「各ページの中身」を別々に書いて、スクリプトで組み立てる**（第3版）。
  これが Astro / Hugo / Eleventy などの「静的サイトジェネレーター」がやっていることの正体
- 元データ（templates/ content/ static/）と完成品（docs/）を分けておくと、
  「どこを直せばいいか」が迷わないし、完成品はいつでも作り直せる

## 手元で見る

`docs/index.html` をダブルクリック（build.py を実行したあと）。

## 直して公開する（毎回この5手順）

1. ファイルを直す
   - 文言 → `content/○○.html`
   - 全ページ共通の部分（メニュー・フッター） → `templates/base.html`
   - 色や余白 → `static/css/style.css`
   - ページを増やす → `content/新しい名前.html` を作り、`build.py` の PAGES に1行足す
2. `python build.py` … 完成品（docs/）を作り直す
3. `git add -A` … 変更を「次に記録するもの」として選ぶ
4. `git commit -m "何を直したか"` … 変更を1つの記録として残す
5. `git push` … GitHub に送る → 1〜2分でページに反映

## お問い合わせフォームの仕組み

サーバーの代わりに Google Apps Script（Apps Script プロジェクト「音感トレーニング お問い合わせ受付」）で受けています。
送信内容はスプレッドシート「音感トレーニング お問い合わせ」に溜まり、制作者にメール通知が届きます。
送信先URLは `static/js/main.js` の `CONTACT_URL`。

## 注意

- `docs/` の中身は **まるごと公開される**。公開したくないファイルは置かない。
- 個人情報（住所・電話・本名など）や、他人の著作物（教材・写真）は載せない。
